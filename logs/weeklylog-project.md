

# Final Project Learning Log

## Note on Structure

I want to briefly acknowledge that this learning log is structured a little differently from the suggested format. I chose to organize it in a way that better reflects how I actually experienced this project. This format captures my learning process more naturally and helps me explain what actually challenged me and helped me grow.

---

## What I Built

For my final project, I built **InternTrack**, an internship and job application tracker that helps organize applications, track statuses, and store important details. I wanted to create something that I would actually use during recruiting, rather than just completing a technical requirement.

---

## What I Learned

### 1. Understanding Structure Across Front End and Back End

One of the most valuable parts of this project was understanding how everything connects. Instead of working on isolated pieces like in earlier assignments, I had to think about how the front end and back end interact as one system.

Using what I learned in WebTech, I was able to connect concepts like user input, routing, and displaying data to Python logic on the back end. This made me feel like I was not just writing code anymore, but actually building an application.

This honestly felt like a full circle moment because I could see how different parts of my coursework came together into something real.

---

### 2. Applying WebTech Knowledge in a New Context

Even though this is a Python project, I found myself constantly relying on what I learned in WebTech. Thinking about:

* how users interact with the interface
* how data flows between pages
* how to structure inputs and outputs

helped me design the project more intentionally.

It made me realize that technical skills are not separate by class. They build on each other, and this project was where that finally clicked for me.

---

### 3. Deployment Challenges and Real World Friction

One of the biggest challenges I faced was deployment. Getting the app to actually run outside of my local environment was much harder than expected.

I ran into issues with:

* missing dependencies and requirements.txt
* import errors and environment mismatches
* confusion between frameworks like Flask and Streamlit

This showed me that building something locally is only part of the process. Making it usable and accessible is a completely different challenge.

Even though it was frustrating, it gave me a much more realistic understanding of what it takes to ship a project.

---

### 4. Thinking Like a Builder, Not Just a Student

Earlier in the course, I focused on completing assignments correctly. With InternTrack, I had to think about usability and design decisions.

I started asking:

* Would I actually use this
* Is this easy to update
* Does this make my workflow better

This shift in mindset was one of the most important things I learned.

---

### 5. Data Structuring and Practical Use

Working with application data forced me to think carefully about how to structure information. Using dictionaries and lists felt more meaningful because I was organizing real information like company names, roles, and statuses.

This reinforced my understanding of Python fundamentals in a much more applied way.

---

## Challenges I Faced

The biggest challenge was definitely deployment and debugging across different parts of the system. It was difficult to identify whether issues were coming from the front end, the back end, or the environment itself.

Another challenge was resisting the urge to overcomplicate the project. I had to continuously step back and focus on making the core functionality work well.

---

## What I Would Improve

If I continue working on InternTrack, I would:

* Successfully deploy it so it is accessible beyond local use
* Improve the UI to make it more intuitive and visually clean
* Add features like filtering, analytics, or reminders
* Integrate APIs to automatically pull job postings

---

## Final Reflection

This project felt like a turning point for me. It brought together Python, WebTech, and even my experience from other classes into one place.

What stood out the most was that this no longer felt like just a class project. It felt like something I built with a real purpose.

The deployment struggles, the structure confusion, and the debugging all made the process harder, but also much more meaningful. It showed me that building something real is messy, but that is also where the most learning happens.

More than anything, this project gave me confidence that I can contribute to both the front end and back end of a project, and actually understand how everything connects.
